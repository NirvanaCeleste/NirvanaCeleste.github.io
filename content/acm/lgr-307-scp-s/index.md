## A - 档案 / file（P17722）
https://www.luogu.com.cn/problem/P17722

> **简要题意**（概括）：n 份档案排成一排、m 轮操作。基础总代价是 $1+2+\dots+n$ 乘以 $m$；第 $i$ 轮给出 $l_i$ 个询问值 $b$，每个 $b$ 的额外代价是排好序后严格大于它的档案数。轮次可以自由重排，轮内 $b$ 的顺序也可以重排，最小化总代价。（概括不保证逐字准确，原题面登录可见。）

**代码**

```cpp
#include <bits/stdc++.h>
using namespace std;
#define ll long long
const int maxn = 1e6+1;
ll n,m;
ll a[maxn],bvlu[maxn];
ll ans;

int main(){
  cin>>n>>m;
  for(int i=1;i<=n;i++) cin>>a[i];
  sort(a+1,a+1+n);//阴

  ans = 1LL * n * (n + 1) / 2;
  ans *= m;

  for(int i=1;i<=m;i++){
    int l,b;
    cin>>l;
    for(int j=1;j<=l;j++){
      cin>>b;
      ll vlu = (a+1+n) - lower_bound(a+1,a+1+n,b);
      bvlu[i] += vlu;
    }
  }

  sort(bvlu+1,bvlu+1+m);
  for(int i=1;i<=m;i++) ans += bvlu[i] * 1LL * (m - 1LL * i + 1LL);

  cout<<ans;
  return 0;
}
```

### 做法与教训

赛时的画图推导（就是这张手绘图，圆圈是档案，红圈是额外代价，绿色是公式）：

{{< figure src="A.png" caption="A 题赛时手绘推导：圆圈为档案，红圈为额外代价，绿色为总代价公式" >}}

拆解出来是两层贪心：

1. **基础部分**：不管怎么操作，$1+2+\dots+n$ 每轮都在，即 $n(n+1)/2 \times m$ 先拿死。
2. **额外部分**：第 $i$ 轮里每个询问值 $b$ 的代价 = 排好序后严格大于 $b$ 的元素个数，用排序后后缀计数 $O(\log n)$ 求出每轮的 $bvlu_i$；轮次可重排，由排序不等式把 $bvlu$ **升序**配最大的系数，即 `ans += bvlu[i] * (m - i + 1)`。

赛时两个坑全踩了又都爬出来了：大样例偏大 → 发现 $a$ **初始无序**要先 sort；担心爆 long long → 算了一下 $n(n+1)/2 \times m$ 与 $bvlu \times m$ 的量级，$10^{18}$ 内装得下。教训是「先 sort」这种题面隐含步骤，靠大样例兜底不如开题时就把数据浇进去想一遍。

## B - 函数 / func（P17723）
https://www.luogu.com.cn/problem/P17723

> **简要题意**：给定长 $n$（$n \le 2 \times 10^6$）的非负整数数组（$a_i < 2^{30}$），求 $\sum_{l \le r} f(l, r)$，其中 $f(l, r) = \mathrm{OR}(l, r)\ |\ \mathrm{mex}(l, r)$，OR 为区间按位或，mex 为区间内未出现的最小非负整数。答案对 $2^{64}$ 取模——`unsigned long long` 自然溢出即可。

**代码**（节选；斜体注释为复盘时补注，其余与赛时源码一致）

```cpp
void solve1(){//最简单不过脑子的模拟 O(n^3)
  for(int l=1;l<=n;l++)
    for(int r=l;r<=n;r++){
      ull res = 0; set<int> S;
      for(int i=l;i<=r;i++) res |= a[i],S.insert(a[i]);
      ull mex = 0;
      while(S.count(mex)) mex++;
      ans += res | mex;
    }
}

int cnt[1<<21];

void solve2(){
  vector<pair<ull,ull>> cur,nxt;
  for(int r=1;r<=n;r++){                      // OR 段维护：固定 r，每个 l 的 OR 值
    nxt.clear();
    nxt.push_back(make_pair(a[r],1ULL));      // 只有 O(log V) 段
    for(int i=0;i<(int)cur.size();i++){
      ull nv = cur[i].first | a[r];
      ull c  = cur[i].second;
      if(nxt.back().first == nv) nxt.back().second += c;
      else nxt.push_back(make_pair(nv,c));
    }
    cur = nxt;
    for(int i=0;i<(int)cur.size();i++) ans += cur[i].first * cur[i].second;
  }

  for(int k=0;k<=20;k++){                     // mex 拆位
    ull sz = 1ULL<<k;
    if(sz > (ull)n) break;
    int l = 1, bl = 1;
    ull d = 0;
    for(int r=1;r<=n;r++){
      if((a[r]>>k)&1){                        // 含第 k 位值的区间由 OR 部分覆盖
        for(int i=bl;i<r;i++) if(a[i] < sz) cnt[a[i]] = 0;
        bl = r+1; l = bl; d = 0;
        continue;
      }
      if(a[r] < sz){
        if(cnt[a[r]]++ == 0) d++;
      }
      while(d == sz){                         // 窗口刚好集齐 [0, 2^k)
        if(a[l] < sz && cnt[a[l]] == 1) break;
        if(a[l] < sz){
          cnt[a[l]]--;
          if(cnt[a[l]] == 0) d--;
        }
        l++;
      }
      if(d == sz) ans += sz * (ull)(l - bl + 1);
    }
    for(int i=bl;i<=n;i++) if(a[i] < sz) cnt[a[i]] = 0;
  }
}
```

### 做法与教训

这场最硬的一题，赛时走了三个弯路又拐回来三次：

1. 先猜整个答案可以按「或」展开：$x|x=x$，多个区间的 OR 合起来就是所有数的「|和」——写小程序验证时发现**总答案是对每个区间的 $f$ 求和（$\sum f$），不是把所有 $f$「或」起来**，全局展开推倒。
2. 拆位切入：按位看，$f$ 的第 $k$ 位 $= \mathrm{OR}$ 的第 $k$ 位 $|$ $\mathrm{mex}$ 的第 $k$ 位。OR 部分对所有区间无条件累加；mex 还能不能在这位上「补」出新的贡献，才是要单独统计的东西。
3. 关键转折：**OR 是单调的**。固定右端点 $r$，左端点从 $r$ 往左扫，$\mathrm{OR}(l,r)$ 的取值只有约 $\log V \approx 30$ 段。倒序枚举 $r$，维护「(OR 值, 左端点个数)」的段向量，新来一个 $a_r$ 就把所有段的值 `| a_r` 再合并相同相邻段——OR 部分的贡献 $O(n \log V)$ 解决。

mex 部分逐位统计，关键约束是：**区间内只要含第 $k$ 位为 1 的值，OR 的第 $k$ 位就是 1，这一位的贡献已被 OR 部分覆盖**——所以 mex 只需要在「不含第 $k$ 位值的极大连续段」里统计。段内所有值都 $< 2^k$，此时双指针维护「值 $< 2^k$ 的互异个数」，恰好等于 $2^k$ 就说明 $[0, 2^k)$ 全部出现、mex 恰好等于 $2^k$，该位贡献 $2^k \times$ 窗口数。两个循环都是 $O(n \log V)$。

遗憾在于写完直接交了（剩 56 分钟），没有造任何小数据验证——OI 赛制交上去也看不到反馈。放榜 80 分：正解部分完全是对的，solve2 在 $n = 2\times10^6$ 的最大测试点上 291 ms 跑完；丢的 20 分全在测试点 3~6——`n ≤ 5000` 走了 $O(n^3)$ 的 solve1 兜底，$n=5000$ 时约 $2\times10^{10}$ 次运算，1 秒时限必炸。赛后教训：**OI 没有反馈，兜底暴力也必须先估复杂度——正确性可以赌，复杂度不能赌**（$n^3$ 只兜得动 $n \le 300$ 量级）。赛后 00:54 删掉暴力分支全跑 solve2，补题 AC。

## C - 路短最 / path（P17724）
https://www.luogu.com.cn/problem/P17724

> **简要题意**：给定 $n$ 点 $m$ 边的无向连通**仙人掌**（一条边至多在一个简单环中），边权均为 1。对这张图跑「Artskjid 算法」：维护二元组集合 $S$（初始 $\{(1,0)\}$）与 $d$ 数组；每步取出 $S$ 中**第二元（$\delta$）最大**的二元组（同为最大取第一元最小的），若 $\delta \ne d_u$ 则直接丢弃这个失效元素；否则 $C$ 加一，并对所有邻居做 $d_v > d_u + 1$ 的松弛，松弛成功就把 $(v, d_v)$ 放回 $S$。求算法结束时 $C$ 的值。多测。

**代码**（节选）

```cpp
void solve1(int n,int m){
  /* 题面算法的照抄：最大堆取 δ 最大的二元组，
     δ ≠ d_u 的失效元素直接跳过，
     新鲜弹出的次数累加进 C */
  priority_queue<pair<int,int>> pq;
  pq.push({0,-1});
  ll C = 0;
  while(!pq.empty()){
    auto pr = pq.top(); pq.pop();
    int delta = pr.first, u = -pr.second;
    if(delta != d[u]) continue;
    C++;
    for(int v : G[u]) if(d[v] > d[u]+1){ d[v] = d[u]+1; pq.push({d[v],-v}); }
  }
  cout<<C<<"\n";
}
```

放榜 15 分：照抄的模拟**语义完全正确**——最大堆取 δ 最大、失效跳过、松弛、C 计数，和题面一一对应；测试点 1~3（n ≤ 3000）全 AC，其余 17 个点全部 TLE 顶满 3.5 秒。所以「建模理解偏」是冤枉自己了：错的不是模型，是复杂度——题面给的「取 δ 最大」算法重复入堆没有多项式保证，正解必须吃仙人掌的结构。数据范围也在明示：特殊性质全在环上（环大小 ≤ 5 / ≤ 20、环个数 ≤ 20），暗示按环处理。

教训：**卡住时重读题面找暗示词**（时限、值域、特殊性质都在提示方向）——这场比赛的特殊性质表就是答案的一半，赛时没有往「按环分类」上想。

### 做法与教训

开场就「真没啥思路，暴力感觉也写不出来」——突破口有两个：

1. **候选 $x$ 收敛**：最优解里的 $x$ 只需要考虑 $a_i$ 和 $a_i \oplus a_j$ 两类（异或出数组里没有的值可以替换成这两类之一而不劣），有点线性基筛选候选元的味道。
2. **0/1 快判**：答案 0 = 本来非降；答案 1 = 存在 $c$ 使整段异或 $c$ 后非降——对每对相邻元素找最高异位 $k$，比较结果由 $c$ 在第 $k$ 位的取值决定，逐对约束冲突检测即可。

两个快判都写了，但「答案 ≥ 2 怎么搜」没落地，最后输出上界 $n$。更扎心的是**写完才发现比赛已经结束**（存盘 18:36，终场 18:30）——D 的提交根本没交上去，0 分离场。赛后把这份代码补测：6 分，3 个小点 AC，中间的点 WA、大点 TLE。
